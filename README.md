# OpenCode in Actions 🚀

Автономный запуск ИИ-агента [OpenCode](https://opencode.ai) внутри GitHub Actions для автоматизации разработки, рефакторинга и генерации Pull Request'ов.

---

## 🎁 Бесплатные модели (работают сразу, без API-ключей и без регистрации!)

OpenCode предоставляет официальные бесплатные модели, которые работают «из коробки» без необходимости вводить какие-либо ключи или регистрироваться:

| Модель | Описание | Нужен ли API-ключ? |
| :--- | :--- | :--- |
| **`opencode/deepseek-v4.1-flash-free`** *(по умолчанию)* | Мощная модель от DeepSeek, отлично пишет код, правит файлы и решает задачи | ❌ **Не нужен (бесплатно)** |
| **`opencode/nemotron-3.5-lightning-free`** | Быстрая модель от NVIDIA | ❌ **Не нужен (бесплатно)** |
| **`opencode/glm-5.3-flash-free`** | Модель серии GLM Flash | ❌ **Не нужен (бесплатно)** |
| **`opencode/mimo-v2.6-flash-free`** | Модель Mimo Flash | ❌ **Не нужен (бесплатно)** |

Также поддерживаются стандартные платные модели (требуют добавления соответствующего ключа в Secrets):

## 📌 Как запустить вручную через интерфейс GitHub Actions

1. Перейдите во вкладку **Actions** в репозитории на GitHub.
2. В левой колонке выберите воркфлоу **OpenCode AI Agent**.
3. Нажмите выпадающую кнопку **Run workflow** справа.
4. Заполните параметры:
   - **Запрос для OpenCode (Prompt)**: текст задания для агента (например: `Создай функцию валидации email на TypeScript с тестами`).
   - **Модель LLM**: по умолчанию выбрана бесплатная `opencode/deepseek-v4.1-flash-free`.
   - **Режим агента**:
     - `build` — полный доступ: анализ, изменение и создание файлов, генерация кода.
     - `plan` — режим планирования и анализа без изменения кода.
   - **Создать Pull Request**: галочка (включена по умолчанию). При наличии изменений агент автоматически создаст новую ветку и откроет Pull Request.
   - **Имя ветки**: можно указать свое имя (например, `feature/email-validator`) или оставить пустым (будет сгенерировано автоматически: `opencode/run-<run_id>`).
5. Нажмите зеленую кнопку **Run workflow**.

## 📊 Где посмотреть результаты выполнения

Воркфлоу спроектирован так, чтобы результаты можно было смотреть максимально удобно и в одном месте:

1. **Job Step Summary (Сводка запуска)**:
   - Откройте завершившийся запуск воркфлоу.
   - В самом низу вкладки **Summary** отображается готовый Markdown-отчет:
     - Таблица параметров (модель, промпт, статус завершения).
     - Список всех измененных или созданных файлов (`git status`).
     - Интерактивный спойлер **Git Diff** со всеми правками кода.
     - Прямая ссылка на созданный **Pull Request** (или ветку с кодом).
     - Спойлер с полным логом ответа консоли OpenCode.
2. **Автоматический Pull Request**:
   - Если агент изменил или добавил файлы и была включена опция `create_pr`, в репозитории автоматически создается Pull Request со ссылкой на запуск Actions и описанием промпта.
   - Вы можете сразу посмотреть изменения во вкладке **Files changed** на GitHub и смерджить их.
3. **Артефакты сборки (Artifacts)**:
   - В блоке **Artifacts** каждого запуска доступен ZIP-архив `opencode-artifacts-<run_id>`, содержащий:
     - `changes.patch` — чистый файл патча `git diff`.
     - `changed_files.txt` — список затронутых файлов.
     - `opencode_output.log` — полный текстовый лог работы OpenCode.
4. **Консоль раннера**:
   - Стандартные логи шагов выполнения Actions доступны в реальном времени.

## ⚡ Оптимизация скорости и вопрос сборки в Docker

### Нужна ли сборка в отдельный Docker-образ?

**Короткий ответ: для скорости сборка Docker-образа в CI не требуется.**

1. **OpenCode не компилируется из исходников:**
   - Разработчики OpenCode предоставляют официальные готовые pre-compiled бинарные сборки для Linux x64 (standalone binary).
   - `curl -fsSL https://opencode.ai/install | bash` скачивает готовый файл за 3–4 секунды.
2. **Кэширование через `actions/cache`:**
   - В воркфлоу настроен кэш директории `~/.opencode/bin`.
   - Начиная со второго запуска, бинарник восстанавливается из кэша GitHub Actions за **менее чем 1 секунду**!
3. **Почему Docker в GitHub Actions был бы медленнее:**
   - Стандартные раннеры GitHub Actions — одноразовые виртуальные машины (`ubuntu-latest`).
   - Скачивание (`docker pull`) базового образа даже из GHCR занимает 15–30 секунд при каждом запуске.
   - Прямой запуск кэшированного бинарника в среде хоста Actions стартует практически мгновенно (~1–3 секунды).

### Когда Docker полезен:
В репозиторий добавлены `Dockerfile` и `docker-compose.yml`:
- Для локальной разработки и тестирования в изолированном контейнере.
- Если в перспективе проекту понадобятся специфические системные утилиты или библиотеки, можно опубликовать контейнер в GitHub Container Registry (GHCR) и использовать директиву `container:` в джобе Actions.

## 🔑 Платные Secrets (API-ключи, опционально)

Если вы хотите использовать платные модели вместо встроенных бесплатных, добавьте соответствующий API-ключ:

1. Перейдите в **Settings** репозитория -> **Secrets and variables** -> **Actions**.
2. Нажмите **New repository secret**.
3. Добавьте один или несколько ключей:
   - `ANTHROPIC_API_KEY` — для моделей Anthropic Claude
   - `OPENAI_API_KEY` — для моделей OpenAI
   - `GEMINI_API_KEY` — для моделей Google Gemini
   - `OPENROUTER_API_KEY` — для OpenRouter
   - `DEEPSEEK_API_KEY` — для DeepSeek

> **Примечание по правам доступа:**
> В воркфлоу настроены `permissions: contents: write` и `pull-requests: write`. 
> Убедитесь, что в **Settings** -> **Actions** -> **General** в секции **Workflow permissions** включены:
> **Read and write permissions** и галочка **Allow GitHub Actions to create and approve pull requests**.
